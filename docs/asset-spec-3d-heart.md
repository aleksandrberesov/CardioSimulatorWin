# Контракт контент-пакета 3D-сердца (для заказчика и 3D-художника)

> **Принцип.** Приложение — это **только просмотрщик**. В нём **нет никакого редактирования** (ни точек-аннотаций, ни пути проведения, ничего). **Все** функции и внешний вид 3D-вида задаются **заранее подготовленными файлами**. Приложение читает готовый набор файлов и показывает интерактивный 3D-вид со всеми функциями.
>
> **Итоговая форма поставки** — **один зашифрованный пакет** (`.pak`), чтобы конечный пользователь (студент) не мог извлечь модель и контент. Упаковка/шифрование — **следующий шаг** (см. §12); сейчас задача — **полностью определить набор файлов**, который готовят заказчик и его 3D-художник.
>
> Все **технические идентификаторы** (имена файлов, мешей, ключи JSON, форматы) — латиницей и **точь-в-точь**: приложение парсит их буквально. Русский текст — пояснения; ASCII-токены — обязательны. JSON — **UTF-8**.
>
> Первоисточник требований: `ТЗ 3д модели сердца 1.docx` (заказчик, 2026-08-26).

---

## 1. Как это работает

1. **3D-художник** создаёт модель со всеми слоями и текстурами (§4–§7).
2. **Заказчик** (врач/методист) готовит текстовые метаданные — названия, зоны, отведения, тайминги, подписи (§5–§10) в виде JSON.
3. Всё складывается в **одну папку** с фиксированными именами файлов (§3).
4. Папка **упаковывается в зашифрованный `.pak`** (§12) и поставляется с приложением или подгружается.
5. Приложение читает пакет **в памяти** (без распаковки на диск) и рисует 3D-вид со всеми функциями.

**Отсутствующий файл = функция просто скрыта.** Поэтому набор можно готовить итерациями: начать с минимальной поставки (§15) и добавлять слои по одному.

## 3. Полный перечень файлов

Все файлы лежат рядом, базовое имя — **`heart`**. Обяз. = без него функция не работает; Опц. = улучшает/уточняет.

| Файл | Кто | Обяз./Опц. | Питает функцию |
|---|---|---|---|
| `heart.manifest.json` | Заказчик | **Обяз.** | Точка входа: версия, заголовок, имя модели, карта файлов |
| `heart.glb` | Художник | **Обяз.** | Сама 3D-модель со всеми слоями/анимацией/локаторами |
| `heart.healthy.png` | Художник | Опц.¹ | Здоровая текстура (старт инфаркта) |
| `heart.infarct.png` | Художник | Опц.¹ | Некротическая текстура (почернение) |
| `heart.territories.png` | Художник | Опц.² | Атлас зон кровоснабжения (раскраска + выбор зоны инфаркта) |
| `heart.coronaries.json` | Заказчик | Опц.² | Названия ветвей, зона и отведения по каждой артерии |
| `heart.territories.json` | Заказчик | Опц.² | Соответствие цвет атласа → зона → артерия |
| `heart.hotspots.json` | Заказчик | Опц. | Точки-аннотации (подписи анатомии) |
| `heart.conduction.json` | Заказчик | Опц.³ | Переопределение таймингов/узлов проводящей системы |
| `heart.layers.json` | Заказчик | Опц.⁴ | Ручная привязка мешей к слоям (если имена не по §4) |
| `heart.strings.json` | Заказчик | Опц. | Тексты панелей (описание, заголовки) на RU/EN |

¹ Инфаркт включается при наличии `healthy`+`infarct` (+ атлас зон для привязки к артерии).
² Коронары/зоны/инфаркт-по-артерии работают вместе: атлас + `territories.json` + `coronaries.json`.
³ Проводящая система работает **без** этого файла — по локаторам `cond_node_*` в модели и встроенным клиническим таймингам (§8). Файл нужен только для нестандартных таймингов.
⁴ Нужен только если имена мешей не соответствуют соглашению §4.

## 4. Модель `heart.glb`

| Параметр | Требование |
|---|---|
| Формат | **glTF 2.0 binary (`.glb`)**, один файл. |
| Оси | glTF-стандарт: правосторонняя, **+Y вверх, +Z на зрителя**. |
| Ориентация | Передняя поверхность → **+Z** (вид по умолчанию), основание → **+Y**, верхушка вниз. |
| Центр/масштаб | Центрировать у геометрического центра; единый масштаб для всех слоёв (реальное сердце ≈ 0.12 м). |
| Геометрия | Только **треугольники**; стенки с толщиной (читаются в разрезе). |
| Полигонаж | Суммарно **≤ 500k tris** (приложение работает и на Android). |
| Материалы | PBR metallic-roughness. **Важно:** импортёр читает материал как **Phong (base color + normal)** — опирайтесь на base color + tangent-space normal map. |
| Текстуры | **2048²** (макс. 4096²); базовые albedo/normal реалистичной кожи можно встроить в `.glb`. |

### 4.1 Слои = меши с префиксами

| Префикс | Слой |
|---|---|
| `heart_real_*` | Реалистичная кожа (вид по умолчанию) |
| `heart_edu_*` | Учебная кожа (приложение делает её **полупрозрачной**; сквозь неё читаются проводящая система/коронары) |
| `coro_<CODE>_*` | Ветвь коронарной артерии, `<CODE>` из §5 |
| `cond_*` | Геометрия проводящей системы (яркая/светящаяся) |
| `leads_*` | Электроды/провода отведений |
| `scaffold_*` | Силуэт тела / вспомогательное |

Обе кожи — в одном файле, с единой ориентацией/масштабом/центром и корректной UV (§13).

### 4.2 Локаторы узлов проводящей системы (для анимации без редактирования)

Так как в приложении нет редактора пути, **анкеры проводящей системы задаёт художник** — пустышками (empty/locator), названными по ключу узла. Приложение строит путь волны деполяризации по ним, тайминги/подписи берёт встроенные (§8).

Обязательные локаторы: `cond_node_sa`, `cond_node_atria`, `cond_node_av`, `cond_node_his`, `cond_node_bundles`, `cond_node_purkinje`, `cond_node_apex`. Ставить в анатомически верных точках (СА-узел → … → верхушка).

### 4.3 Анимация сокращения

Один клип полного сердечного цикла, имя **`beat`** (если клип один — берётся первый). Зациклен (старт=финиш), ~**30 fps**, **без root-motion**. Скелетная или morph — оба подходят. Приложение подгоняет скорость под ЧСС и синхронизирует с волной деполяризации.

## 5. Коронарные артерии + `heart.coronaries.json`

Слой `coro_*` разбит на ветви; **каждая ветвь — отдельный меш** `coro_<CODE>_*`. По клику приложение показывает название и подсвечивает ветвь.

Коды (латиница — обязательна; названия — в JSON): `LM`, `LAD`, `D1`, `D2`, `S1`, `LCX`, `OM1`, `OM2`, `RCA`, `AM`, `PDA`, `PLB`. Минимум для инфаркта — три магистральных: **`LAD`, `LCX`, `RCA`**.

```json
{
  "version": 1,
  "vessels": [
    { "code": "LAD", "parent": "LM", "territory": "ANTEROSEPTAL",
      "name_ru": "Передняя межжелудочковая ветвь (ПМЖВ)",
      "name_en": "Left anterior descending",
      "affectedLeads": ["V1","V2","V3","V4"] },
    { "code": "LCX", "parent": "LM", "territory": "LATERAL",
      "name_ru": "Огибающая ветвь (ОВ)",
      "name_en": "Left circumflex",
      "affectedLeads": ["I","aVL","V5","V6"] },
    { "code": "RCA", "parent": null, "territory": "INFERIOR",
      "name_ru": "Правая коронарная артерия (ПКА)",
      "name_en": "Right coronary artery",
      "affectedLeads": ["II","III","aVF"] }
  ]
}
```

## 6. Зоны кровоснабжения: `heart.territories.png` + `heart.territories.json`

**Атлас-карта зон** (не геометрия): та же UV-развёртка, что у кожи и карт инфаркта. Каждой зоне — **плоский ключевой цвет**, **жёсткие границы без сглаживания**; фон вне зон — `#000000`.

```json
{
  "version": 1,
  "atlas": "heart.territories.png",
  "territories": [
    { "code": "ANTEROSEPTAL", "vessel": "LAD", "keyColor": "#FF3B30",
      "name_ru": "Передне-перегородочная область", "name_en": "Anteroseptal" },
    { "code": "LATERAL", "vessel": "LCX", "keyColor": "#34C759",
      "name_ru": "Боковая стенка", "name_en": "Lateral" },
    { "code": "INFERIOR", "vessel": "RCA", "keyColor": "#0A84FF",
      "name_ru": "Нижняя стенка", "name_en": "Inferior" }
  ]
}
```
`keyColor` — точный цвет зоны в атласе. Ориентир (референс R6): окклюзия **LAD** → передне-перегородочная зона → изменения в **V1–V3**.

---

## 7. Текстуры инфаркта (плавное почернение)

Приложение смешивает «здоровую» и «некротическую» текстуры по прогрессу 0→1, ограничивая почернение зоной выбранной артерии (§6). Все карты — **одна UV, одно разрешение**.

- `heart.healthy.png` — albedo здорового миокарда (обычно = base color реалистичной кожи).
- `heart.infarct.png` — та же развёртка, ткань затемнена/почернела органично (не плоский `#000000`).
- Область почернения выбирается **атласом зон** `heart.territories.png` по выбранной артерии.

Совместимость: если зон ещё нет, можно временно дать `heart.mask.png` (серая маска: белое = где допустимо почернение) — инфаркт будет «на всё сердце», без привязки к артерии.

## 8. Проводящая система (без редактирования в приложении)

- **Визуал** — меши `cond_*` (§4.1): яркие, читаются сквозь полупрозрачную учебную кожу (референс R4/R7).
- **Путь анимации** волны — по локаторам `cond_node_*` (§4.2). Тайминги и подписи узлов **встроены** в приложение (клинический шаблон: СА 0 мс → предсердия 60 → АВ 100 → Гис 170 → ножки 190 → Пуркинье 210 → верхушка 245; задержка АВ = сегмент PR).
- **Разрез** («половина сердца») приложение делает само секущей плоскостью — отдельная разрезанная геометрия не нужна.
- `heart.conduction.json` — **опционально**, только чтобы переопределить тайминги/узлы явными координатами:
```json
[
  { "key": "sa",  "labelRu": "СА-узел",       "labelEn": "SA node",       "anchor": [0.0, 1.2, 0.3], "arrivalMs": 0 },
  { "key": "av",  "labelRu": "АВ-узел",       "labelEn": "AV node",       "anchor": [0.0, 0.4, 0.1], "arrivalMs": 100 },
  { "key": "apex","labelRu": "Верхушка",      "labelEn": "Apex",          "anchor": [0.0,-1.1, 0.0], "arrivalMs": 245 }
]
```

## 9. Аннотации: `heart.hotspots.json` (опционально)

Так как редактора нет, подписи анатомии готовятся файлом. Точка привязывается к координате модели; приложение показывает маркер и карточку.

```json
[
  { "anchor": [0.6, 0.2, 0.9],
    "titleRu": "Левый желудочек", "titleEn": "Left ventricle",
    "descRu": "Основная насосная камера.", "descEn": "Main pumping chamber." }
]
```

## 10. Манифест: `heart.manifest.json` (обязателен)

Точка входа пакета. Имена файлов по умолчанию — конвенционные (§3); секцию `files` можно опустить, если имена стандартные.


## 11. Прочее (опционально)

- `heart.layers.json` — ручная привязка мешей к слоям, если имена не по §4 (ключи слоёв: `EducationalSkin`, `RealisticSkin`, `Coronaries`, `Conduction`, `Leads`, `Scaffold`; для коронаров — карта `CODE → [имена мешей]`).
- `heart.strings.json` — тексты панелей UI (описание/заголовки) на RU/EN, если нужно переопределить встроенные.

## 12. Упаковка в зашифрованный пакет (следующий шаг)

Цель — чтобы пользователь **не мог извлечь** модель и контент. Приложение уже умеет это для медицинского контента и **переиспользует тот же механизм**:

- Все файлы `heart.*` из папки → **ZIP** → **шифрование AES-256-GCM** в контейнер **`.pak`** (та же схема `ContentCrypto`/CSP2, что у `pathologies.pak`/`courses.pak`).
- Приложение читает записи **лениво, в памяти** (`EncryptedArchive`), без распаковки на диск — как уже работает для контента.
- Итоговый файл, например, **`heart3d.pak`**, поставляется с приложением или подгружается пользователем (как модель сейчас в §Settings).

От заказчика/художника на этом шаге ничего дополнительно не требуется — только готовый набор файлов §3. Сборку `.pak` делает инструмент упаковки (как для контент-паков).

## 13. Технические требования и «подводные камни»

- **UV-развёртка обязательна** для кожи: непересекающаяся, в `[0,1]`, **общая** для `albedo / normal / healthy / infarct / territories` — иначе инфаркт и зоны «съедут».
- **Границы зон** в атласе — жёсткие, без anti-alias/bleed.
- **Некроз** — органичное затемнение, не чистый чёрный.
- **Нормали + UV** обязательны; тангенты приложение выведет само.
- **Полупрозрачность** учебной кожи: без самопересечений/грязной внутренней геометрии.
- Единый масштаб/ориентация/центр для всех слоёв и обеих кож; **триангуляция**; разумный полигонаж (Android).
- Имена файлов/токенов — **латиница, точное совпадение**; JSON — **UTF-8**.

## 14. Чек-лист приёмки

- [ ] `heart.manifest.json` валиден, указывает `heart.glb`.
- [ ] `heart.glb`: ориентация (перед→+Z, основание→+Y), единый масштаб.
- [ ] Меши `heart_real_*` и `heart_edu_*`; учебная корректна в полупрозрачности.
- [ ] Ветви `coro_<CODE>_*` (минимум `LAD`, `LCX`, `RCA`); коды совпадают с `coronaries.json`.
- [ ] Локаторы `cond_node_*` во всех 7 точках; меши `cond_*` яркие.
- [ ] Слой `leads_*`/`scaffold_*` — отдельные меши.
- [ ] UV общая; `healthy/infarct/territories` совпадают по развёртке и разрешению.
- [ ] Атлас зон — плоские цвета, жёсткие границы; цвета = `territories.json`.
- [ ] Клип `beat` — один бесшовный цикл, без root-motion, ~30 fps.
- [ ] Все JSON — валидный UTF-8; имена файлов по §3.

## 15. Минимальная поставка для старта

1. `heart.manifest.json` + `heart.glb` с одним мешом `heart_real_myocardium`, базовым albedo, правильной ориентацией/масштабом.
2. (желательно) `heart_edu_myocardium` — вторая кожа.

Дальше слои добавляются по одному (коронары → зоны+инфаркт → проводящая (локаторы) → отведения → анимация); каждый включает свою функцию, не ломая готовое.
